# pocket_calibre

Клиент calibre content server для PocketBook 632 (Touch HD 3). Показывает
последние добавленные книги из библиотеки calibre и скачивает их на ридер по
тапу.

## Стек

| Слой | Что используется | Почему |
|---|---|---|
| Биндинги | [`inkview`](https://crates.io/crates/inkview) 0.3 | Единственные живые биндинги к `libinkview`. Грузит библиотеку через `libloading` в рантайме, поэтому SDK PocketBook для сборки не нужен |
| UI | [`inkview-slint`](https://crates.io/crates/inkview-slint) 0.3 + `slint` 1.17 | Slint-бэкенд поверх софтварного рендерера. Декларативный `.slint`, готовые списки со скроллом и обработка тача |
| Сеть | `ureq` 3 | Блокирующий HTTP без async-рантайма |
| Кросс-сборка | `cargo-zigbuild` + `zig` | Заменяет полноценный C-тулчейн под armv7 |

`inkview` собран с фичей `sdk-6-5` — под прошивку `U632.6.5.x`. При смене
прошивки правятся обе строки в `[dependencies]` (`inkview` и `inkview-slint`);
доступны `sdk-5-19`, `sdk-6-5`, `sdk-6-8`, `sdk-6-10`.

## Сборка

Нужны `rustup`, `cargo-zigbuild` и `zig`:

```sh
cargo install cargo-zigbuild
sudo pacman -S zig          # или: pip install --user ziglang
./build-arm.sh
```

На выходе — `dist/pocket_calibre.app` (armv7, EABI5, требует не выше GLIBC_2.18
при доступных на устройстве 2.23).

## Установка

1. Скопировать `dist/pocket_calibre.app` в `/mnt/ext1/applications/` на ридере.
2. Запустить из меню «Приложения» — при первом запуске приложение создаст
   `pocket_calibre.toml` с настройками по умолчанию.
3. Нажать «Настройки» и указать адрес сервера.

## Конфигурация

Настройки правятся двумя способами: кнопкой «Настройки» прямо на устройстве
(тап по полю открывает нативную клавиатуру inkview — см. `src/keyboard.rs`)
либо файлом с компьютера. Экран настроек пишет в тот же файл.

Файл ищется по порядку в `<папка с бинарником>/pocket_calibre.toml`,
`/mnt/ext1/applications/pocket_calibre.toml`,
`/mnt/ext1/system/config/pocket_calibre.toml`.

```toml
server = "http://192.168.1.10:8080"
library = "Calibre_Library"
download_dir = "/mnt/ext1/Books"
formats = ["FB2", "EPUB", "PDF", "MOBI"]
limit = 200
```

Любой ключ можно опустить — недостающие берутся из значений по умолчанию.
`user` и `password` нужны только серверу с авторизацией. `formats` — список по
убыванию предпочтения; качается первый формат, который есть у книги.

Если файл не разбирается, приложение работает на умолчаниях и пишет ошибку в
строку состояния, но файл не перезаписывает — правки, сделанные руками, важнее.

## Почему листание, а не прокрутка

Цикл `inkview-slint` обрабатывает **одно событие за кадр**, где кадр — это
полная софтварная отрисовка плюс обновление e-ink. Палец во время протяжки
даёт порядка 50 `PointerMove` в секунду, и очередь росла быстрее, чем
разгребалась: содержимое уползало за пальцем на пару пикселей в полсекунды.

Дело не только в частоте событий. Область повреждения при прокрутке — весь
список, ≈1072×900 ≈ 965 000 пикселей, и каждый уходит в фреймбуфер отдельным
вызовом `Screen::draw` с двумя проверками границ. Плавная прокрутка тут
недостижима при любой настройке.

Поэтому: `Flickable` убран отовсюду, список нарезается на страницы в Rust,
`PointerMove` не пробрасывается вовсе. Листание — кнопками на экране и
физическими кнопками устройства (`inkview-slint` отдаёт их как стрелки).

Сколько строк влезает на страницу, считает Slint (`rows-per-page`) от
фактической высоты окна: масштаб экрана заранее неизвестен, `scale_factor`
зависит от dpi и scale, которые сообщает прошивка. Базовый размер вёрстки
(`unit`) при этом приходит из Rust — вывести его в `.slint` из `root.height`
не выйдет, получается петля привязок через размеры шрифтов.

## Ограничения

- **Только HTTP, без TLS.** `ureq` собран без rustls, чтобы не утяжелять
  кросс-сборку. Для https нужно включить фичу `rustls`.
- **Только basic-аутентификация.** Calibre по умолчанию (`--auth-mode=auto`)
  использует digest, который здесь не реализован. Сервер надо запускать с
  `--auth-mode=basic` либо вовсе без пароля.
- Нет поиска и фильтров: показываются последние `limit` книг по дате
  добавления.
- Обложки кэшируются только в памяти. При перезапуске страница тянет их заново
  — это 6 запросов по ~10 КБ, дисковый кэш пока не нужен.

## Заметки по зависимостям

Две неочевидные вещи, без которых кросс-сборка не проходит:

**`fontique` в прямых зависимостях.** В коде не используется. Начиная со slint
1.15 `i-slint-core` и `i-slint-renderer-software` зависят от `fontique`
безусловно, а тот тянет `yeslogic-fontconfig-sys`, чей `build.rs` зовёт
pkg-config — и падает, потому что pkg-config не умеет кросс-компиляцию без
sysroot для armv7. Прямая зависимость с фичей `fontconfig-dlopen` через
unification включает её тому же транзитивному `fontique`: libfontconfig
начинает грузиться через `dlopen`, а если её на устройстве нет — `fontique`
штатно отдаёт пустой набор системных шрифтов вместо паники. Нам это подходит,
глифы всё равно вшиты в бинарник.

**`src/libm_shim.rs`.** `tiny-skia` (приезжает как `resvg` → SVG-поддержка
`i-slint-core`, её включает фича `std`) использует `f64::minimum`/`maximum`.
Rust лоуерит их в libm-функции C23 `fminimum_num`/`fmaximum_num`, появившиеся
только в glibc 2.35. На ридере glibc 2.23, и линковка падает — шим определяет
эти четыре символа сам.

Отдельно: набор кириллических глифов перечислен литералом в `ui/app.slint`.
Компилятор Slint встраивает глифы только для латиницы, цифр и строк, найденных
в `.slint`-файле, а названия книг приходят из Rust — без явного списка вместо
них были бы пустые прямоугольники.
